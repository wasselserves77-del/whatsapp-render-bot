# مِيزان | حاسبة دقيقة مع بوت واتساب

موقع عربي باتجاه RTL لجمع الأعداد الصحيحة والعشرية بدقة غير محدودة عمليًا، مع تكامل اختياري مع Evolution API. لا توجد حسابات مستخدمين أو قاعدة بيانات. سجل الحاسبة محفوظ في المتصفح، وإعدادات البوت محفوظة على الخادم.

## التشغيل محليًا

يتطلب Node.js 20 أو أحدث. لا توجد حزم خارجية:

```sh
npm start
```

افتح `http://localhost:3000`. لتشغيل الاختبارات:

```sh
npm test
```

## النشر على Render

1. ادخل إلى Render وأنشئ **New > Web Service**، ثم اربط حساب GitHub والمستودع `wasselserves77-del/whatsapp-render-bot` والفرع `main`.
2. اختر Node كبيئة التشغيل. استخدم أمر البناء `npm install` وأمر التشغيل `npm start`، واضبط فحص الصحة على `/health`.
3. أضف متغيرات البيئة:

	- `NODE_ENV` = `production`
	- `SETTINGS_TOKEN` = رمز عشوائي طويل تحتفظ به؛ يلزم لتعديل إعدادات البوت من صفحة الإعدادات.
	- `DATA_DIR` = `/var/data`
	- `PUBLIC_URL` = اختياري، إذا أردت عنوانًا مخصصًا بدل عنوان Render التلقائي.

4. أضف قرصًا دائمًا للخدمة واجعل مسار الربط `/var/data`. ملف الإعدادات يحوي مفتاح Evolution API؛ القرص الدائم يمنع فقده عند إعادة النشر أو إعادة التشغيل. القرص الدائم متاح حسب خطة Render وقد يترتب عليه تكلفة. من دون قرص دائم، قد تُمحى إعدادات البوت عند إعادة نشر الخدمة.
5. انشر الخدمة وافتح `https://عنوان-الخدمة.onrender.com/settings`.

لا تضع `SETTINGS_TOKEN` أو مفتاح Evolution API في ملفات المشروع أو المستودع. أدخل رمز الإعداد في صفحة الربط عند الحفظ أو اختبار الاتصال؛ لا يُخزن في المتصفح.

## ربط Evolution API

1. جهّز Evolution API وأنشئ Instance، ثم تأكد من اتصال رقم واتساب بها.
2. في صفحة **ربط واتساب** أدخل عنوان Evolution API، اسم الـ Instance، ومفتاح API.
3. أدخل الرابط العام للموقع. على Render يمكن تركه فارغًا ليُكتشف تلقائيًا، أو كتابة رابط الخدمة/النطاق المخصص.
4. أدخل أرقام واتساب المسموح لها، رقمًا دوليًا في كل سطر، ثم احفظ. يضبط الموقع webhook لحدث الرسائل الواردة تلقائيًا.
5. استخدم زر اختبار الاتصال للتأكد من الوصول إلى الـ Instance.

يرد البوت فقط على الرسائل الواردة من الأرقام المسموح بها، ولا يعالج المجموعات أو الرسائل الصادرة من الحساب نفسه. عند أول رسالة يرسل تعليمات الاستخدام. بعد ذلك:

- أرسل الأعداد مفصولة بفاصلة عادية أو عربية، أو اكتب كل عدد في سطر، أو أرسل كل عدد في رسالة منفصلة. استخدم النقطة للكسور، مثل `10.25`.
- لا يرد البوت على رسائل الأعداد؛ يجمعها في جلسة المرسل.
- أرسل `olso` لحساب المجموع الدقيق. تبقى الأعداد في الجلسة حتى تمسحها.
- أرسل `oslo_d` لحذف أعداد جلستك والبدء من جديد. لا يمسح هذا جلسات المستخدمين الآخرين.

الجلسات محفوظة في ذاكرة الخدمة فقط، بلا قاعدة بيانات؛ لذلك إعادة تشغيل الخدمة أو نشر إصدار جديد يمسح الجلسات النشطة. استخدم نسخة واحدة من خدمة الويب حتى لا تتوزع رسائل الجلسة بين أكثر من نسخة.

## البيانات والخصوصية

- لا توجد حسابات أو قاعدة بيانات.
- لا يُعاد إرسال مفتاح Evolution API إلى المتصفح؛ يُحفظ في ملف إعدادات الخادم تحت `DATA_DIR`.
- يقتصر تعديل إعدادات الربط في الإنتاج على من يملك `SETTINGS_TOKEN`.
- سجل عمليات الحاسبة محفوظ في `localStorage` للمتصفح الحالي فقط. زر **حذف كل العمليات السابقة** يمسح السجل والخانات والنتيجة.
- `/health` نقطة فحص صحة الخدمة؛ `/settings` صفحة إعدادات الربط.
